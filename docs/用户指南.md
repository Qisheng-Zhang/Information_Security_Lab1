# S-DES 用户指南

> 信息安全导论 · 作业1：S-DES 算法实现
> 适用版本 1.0.0 ｜ 纯 Python 3 标准库 ｜ 无需安装任何第三方依赖

本指南面向**只负责使用、不修改代码**的同学，覆盖三种使用方式：

- **网页版界面（推荐）**：用浏览器打开，排版清爽、可直接截图交作业，也不依赖 `tkinter`。
- **桌面版界面（tkinter）**：把 5 个关卡的演示集中在一个本地窗口里，适合无浏览器或不想开浏览器的场合。
- **命令行（CLI）**：适合脚本化、批量生成测试数据、自动化验证。

> 网页版与桌面版**共用同一套算法内核**（`sdes/core.py`、`sdes/codec.py`、`sdes/crack.py`），
> 相同输入应得到相同的算法输出。第 2 关的独立实现验证还需使用 `tests/gen_vectors.py` 或搭档的程序；两个界面调用同一内核本身不能替代该验证。

## 1. 环境准备

| 项目 | 要求 |
|---|---|
| Python | 3.10 及以上（开发环境为 3.12.14） |
| 第三方库 | **无**（网页版只用 `http.server`/`json`，桌面版用 `tkinter`，通信与并行是 `socket`/`threading`，全部为 Python 标准库） |
| 操作系统 | Python 与 Tk 可用的平台；提交材料记录的是 Windows 环境，其他平台运行结果需自行核对 |
| 浏览器 | 网页版需要任意现代浏览器（Edge / Chrome / Firefox 等），无需联网，全部在本机运行 |
| 中文显示 | Windows 控制台若出现乱码，先执行 `$env:PYTHONIOENCODING="utf-8"` |

安装步骤：

1. 安装 Python 3.10 或更新版本；桌面版还需 Tcl/Tk 组件，网页版与 CLI 不依赖它。
2. 把整个项目文件夹复制到任意目录（含 `sdes/`、`tests/`、`docs/`、`截图与视频/`）。
3. **所有命令都必须在项目根目录下执行**（即能看到 `sdes/`、`tests/` 的那一层），因为包是按目录结构导入的。

自检是否装好：

```powershell
python -m tests.run_all
```

若最后一行显示 `结果: 全部通过`，说明环境与代码都正常。

## 2. 网页版界面用法（推荐）

### 2.1 启动与访问

```powershell
python -m sdes.webapp                    # 默认 http://127.0.0.1:8000
python -m sdes.webapp --port 8080        # 换端口
python -m sdes.webapp --open             # 启动后自动打开浏览器
```

终端会打印访问地址，把它复制到浏览器打开即可：

```
==================================================================
  S-DES 网页版界面 —— 信息安全导论 作业1
==================================================================
  访问地址: http://127.0.0.1:8000
  前端目录: ...\sdes\web
  Ctrl+C 结束服务
==================================================================
```

**默认监听本机 `127.0.0.1:8000`**，加解密计算由本机 Python 后端完成，浏览器通过本机 HTTP API 传入数据并显示结果。
`--host` 可改变监听地址；第 3 关还可填写其他 TCP 主机，因此数据去向取决于运行参数与页面中的目标地址。
默认本机演示无需联网。用完在终端按 `Ctrl+C` 停止。

应通过上述 HTTP 地址访问页面，直接双击 `sdes/web/index.html` 不能提供后端 API。

> 端口被占用时会出现 `OSError`，换一个端口（如 `--port 8080`）即可。

### 2.2 页面结构

顶部是深色页眉（标题、规格提示、状态灯），下面有 6 个页签：

| 页签 | 对应作业 | 内容 |
|---|---|---|
| 第 1 关 · 基本测试 | 第 1 关 | 单分组加解密 + 逐步跟踪 |
| 第 2 关 · 交叉测试 | 第 2 关 | 生成/下载 CSV 测试向量，与对方的文件比对 |
| 第 3 关 · 扩展功能 | 第 3 关 | 字符串（ASCII/UTF-8）加解密 + TCP Socket 发送 |
| 第 4 关 · 暴力破解 | 第 4 关 | 明密文对穷举 1024 个密钥，含耗时/速率与进度条 |
| 第 5 关 · 封闭测试 | 第 5 关 | 全空间 1024×256 枚举 + 碰撞分布表 + 文字报告 |

右上角的**状态灯**会显示当前动作（就绪 / 加密中 / 出错），请求期间按钮自动禁用，避免重复提交。

### 2.3 第 1 关 · 基本测试

1. 在「明文 (8-bit)」输入 8 位 `0`/`1`，在「密钥 (10-bit)」输入 10 位 `0`/`1`。
   输入里的空格与下划线会被自动忽略，`1001 0111` 与 `10010111` 等价。
2. 点 **加密 →** 得到密文的二进制与十六进制形式，以及两个子密钥 K1/K2。
3. 点 **← 解密** 时，输入框中的 8 位数据作为密文，结果标题切换为明文。验证回环时先把加密得到的密文填回该框，再解密。
4. 点 **逐步跟踪** 展开「过程明细 / 中间状态」表格，逐行列出：

```
P10(K)                 密钥经过 P10 置换
L1|R1 (P10 左5|右5)    分为左右两半
K1 / K2                两个子密钥
IP(P)                  明文经过初始置换
L0 / R0                IP 输出的左右两半
F(R0,K1)               轮函数输出
f_K1(IP(P))            第一轮结束
SW(...)                左右 4-bit 交换
F(L1',K2)              第二轮轮函数输出
f_K2(SW(...))          第二轮结束
IP^-1(...) = C         最终密文
```

这份明细正好对应作业给出的加密公式 `C = IP⁻¹( f_K2( SW( f_K1( IP(P) ) ) ) )`，
**写实验报告时可以直接截图或抄进正文**，用来展示「确实按规格逐步实现了」。

5. **随机明文 / 密钥** 用于现场演示；**清空** 重置全部输入输出。

示例：明文 `10010111`、密钥 `1010000010` 加密得到 `00111000`（hex `38`）；
将 `00111000` 作为解密输入应还原为 `10010111`（hex `97`）。
仓库现有 [第1关_解密.png](../截图与视频/第1关_解密.png) 的输入为 10010111，密钥为 1010000010，输出明文 8C / 10001100，两种表示一致。
这是一组有效解密输入，与解密图 1 所得密文 00111000 不同；图 1 的回环还原需另以 00111000 为解密输入确认。

### 2.4 第 2 关 · 交叉测试

作业要求两人一组、使用**相同的算法流程与转换单元**，验证相同明文与密钥得到相同密文。

1. 选择「生成条数」（默认 200），密钥可留空表示随机，点 **生成测试向量**。
   随机种子固定为 `20261008`，同一实现采用相同条数与固定密钥设置时可重复生成相同序列。
2. 点 **下载 CSV** 保存为文件（列固定为 `pt,key,ct`），发给搭档；
   搭档在自己程序里生成同样的文件后，用 **选择对方 CSV 文件…** 载入。
3. 点 **比对**，页面会显示：

```
一致 200/200 行   两套程序对相同明文与密钥得到完全相同的密文，交叉测试通过 ✓
```

若不一致，会以表格列出前 20 处差异（行号、本机三元组、对方三元组），直接定位到出问题的输入。

网页版比较的是两份 CSV 中同一位置的 `pt,key,ct` 三元组，因此双方应采用相同的输入与行序。
它不会在比对接口中重新计算导入行的密文；应确认对方文件确由独立实现生成。图 4 的结果直接支持 200 行一致，完整输入空间的结论需另附运行记录。

> 也可以不用文件：把对方的 CSV 内容直接粘贴到比对框里再点「比对」即可。

#### 2.4.1 一个人做：用「独立第二实现」代替搭档

独立第二实现可用于算法自检；同一份代码的文件自比对只能检查文件与界面流程。
若提交要求涉及两组同学的实现，应另与搭档程序互验并保留对方来源。

项目里已经提供了 `tests/gen_vectors.py`。它**刻意不 `import sdes`**，
把 P10 / P8 / IP / EP / S 盒等转换单元按作业文档重新抄写了一遍，充当"对方的程序"。
它的密文是由这套独立代码算出来的，与 `sdes/core.py` 的整数位运算实现互为交叉验证。

```powershell
# 一条命令生成"对方"的测试向量文件, 并顺手与本机核心交叉验证
python -m tests.gen_vectors -n 200 -o 对方.csv --check
```

输出：

```
[+] 已写入 对方.csv: 200 条向量 (种子 20261008, 密钥随机)
[i] 下一步: 网页版第 2 关 -> 生成测试向量 -> 选择对方 CSV 文件 -> 比对
[自检] 200 条向量与 sdes.core 比对: 全部一致
```

> `--check` 报告两套实现对这 200 条输入的密文比较结果；它不代表全部 262144 组输入均已验证，也不替代搭档程序的来源证据。

然后在网页里走一遍，把过程截成图：

1. 第 2 关页 → 点 **生成测试向量**（本机实现，200 条）；
2. 点 **选择对方 CSV 文件…** → 选中刚生成的 `对方.csv`（独立实现）；
3. 点 **比对** → 显示 `一致 200/200 行`。

这三步加上 `--check` 的命令行输出，可记录项目内第二实现的抽样验证过程。
截图时建议把**终端里 `[自检] … 全部一致`** 和**网页上 `一致 200/200 行`** 放在同一张图里，
一张图就能说明「两套独立实现结果相同」。

常用参数：

| 参数 | 说明 |
| --- | --- |
| `-n 200` | 生成条数（1~5000） |
| `--key 1010000010` | 固定密钥；留空表示每行随机 |
| `-o 对方.csv` | 写入文件；省略则打印到屏幕 |
| `--check` | 顺便与 `sdes.core` 逐条比对并打印结论 |

> 取样序列与网页版严格一致（同一个种子 `20261008`、同一套随机数调用次序），
> 因此生成出来的 `pt`、`key` 两列与网页版完全相同，**真正被独立计算、用来互相校验的是 `ct` 列**。
> 这正是交叉测试想要的：输入相同、算法各自独立，比较输出。
>
> 桌面版生成随机向量时先取密钥、再取明文，与网页版的调用顺序不同；同一随机种子不保证两种界面的 CSV 逐行相同。

#### 2.4.2 两个人做：与真实的第二组程序互验（推荐）

如果你已经拿到了搭档（第二组）的源代码压缩包，那就**不要再自己造第二实现**了 ——
用对方的真程序互验，证据比 `2.4.1` 的自造实现更硬。项目为此提供了 `tests/cross_test.py`。

**第一步：把对方的包放到项目里（或任意位置）**

对方的源码属于队友的作业，**本仓库不附带**。把它解压到项目根目录下的 `_组2参考\`，
或者放在任何地方再用 `--other` 指过去：

```
<项目根目录>\
└─ _组2参考\            <- 自己新建并解压（仓库中不含此目录）
   └─ SDES\             <- 从 SDES.zip 解压出来，保持原样
      └─ sdes\          <- 对方的 sdes 包（cross_test.py 的默认查找位置）
```

**第二步：一条命令跑完两种方式**

```powershell
python -m tests.cross_test --other "搭档程序\sdes"              # 抽样：5 条预设向量 + 200 条随机
python -m tests.cross_test --other "搭档程序\sdes" --full       # 全空间：1024×256 组
python -m tests.cross_test --other "搭档程序\sdes" --full --md "docs\交叉测试记录.md"
```

`搭档程序\sdes` 是示例路径，运行前替换为真实目录。仓库没有 `_组2参考/`，不提供对方源码时直接运行默认命令会提示找不到实现。

**脚本自动完成五项验证**（对应作业 3.2 的两个"或者"分支）：

| 编号 | 验证内容 | 判定标准 |
| --- | --- | --- |
| [1] | 转换单元逐项比对（P10/P8/IP/IP⁻¹/EP/SPBox/SBox1/SBox2） | 8 项全部一致 |
| [2] | 密钥扩展：1024 个主密钥的 (K1, K2) | 不一致 0 个 |
| [3] | **方式①** 同一 (明文, 密钥) 双方各自加密 | 密文不一致 0 组 |
| [4] | **方式②** 对方加密出的密文 → 我方程序解密 | 还原失败 0 组 |
| [5] | **方式② 反向** 我方加密出的密文 → 对方程序解密 | 还原失败 0 组 |

配套测试报告记载的历史全空间结果（262144 组；复现仍需提供对方源码）：

```

    -> 全部一致 ✓ 方式① 通过
[4] 对方加密 262144 组密文 -> 我方解密还原失败 0 组
    -> 全部还原成功 ✓ 方式② 通过
```

末行 [6] 还会附加第 3 关的字符串互验（`'This is a test'`、`'S-DES'`、`'a'`、`'Hello, CQU!'` 逐字节密文一致）。

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--other <目录>` | 指定对方 `sdes` 包的位置（默认 `_组2参考/SDES/sdes`，本仓库不含该目录，通常需显式指定） |

> 「此处的 S-box2 与 PPT 上面的相比略有改动，以此处为准」实现了改写版。

> 这些差异**不影响**比对结论 —— 交叉测试比的正是"输入输出口径"，不是"代码长得像不像"。

### 2.5 第 3 关 · 扩展功能

**字符串加解密**：在「明文文本」里输入任意 ASCII/UTF-8 字符串，点 **加密 →**，
密文以十六进制显示（每 2 个十六进制字符 = 1 字节 = 1 个 S-DES 分组）。
下方提示会写明字节数、分组数与补位情况。点 **← 解密** 反向还原。

**TCP Socket 通信演示**（需要先启动服务端）：

```powershell
# 终端 A
python -m sdes.server
```

然后在网页里填主机 `127.0.0.1`、端口 `50007`，点 **发送到 TCP 服务端…**，
日志区会逐步显示整个过程：

```
① 本地加密: “信息安全导论” --S-DES--> 111E8F92E71DFEE89DFE66DAFE1DE52EE803
② 连接 127.0.0.1:50007  PING -> PONG
③ 发送 DEC 111E8F92E71DFEE89DFE66DAFE1DE52EE803
④ 服务端解密回显: “信息安全导论”
⑤ 服务端当前密钥: 1010000010
⑥ 校验: 回显与原文一致 ✓
```

客户端的 `DEC` 请求载荷为十六进制密文；服务端解密后以明文应答供客户端校验，`KEY` 命令还会返回演示密钥。
这是本机密文发送与解密回显演示，整个 TCP 会话并非全程只传密文。
若提示「连接被拒绝」，就是服务端没启动；若回显是乱码，说明两侧密钥不一致。

编码下拉框支持 UTF-8、ASCII、GBK，用于页面上方的字符串加解密。
当前 TCP 发送接口固定使用 UTF-8，发送时会重新加密明文，不使用下拉框选定的其他编码或已填的密文。

### 2.6 第 4 关 · 暴力破解

1. 在「明文-密文对」里每行写一组，格式为 `明文,密文`，例如 `10010111,00111000`；多组用换行或分号分隔。
   不知道密文时点 **随机生成一对（已知真钥匙）**，页面会自动填好一组自洽的输入并显示真钥匙（仅演示用）。
2. 设置线程数（默认 8）、每块大小（默认 64），勾选是否使用多线程，点 **开始破解**。
3. 结果区显示 **候选密钥数、遍历密钥数、耗时、速率**，下面按块列出全部候选密钥。

预期现象（与作业说明一致）：

- 单组明密文对可能留下多个候选；固定样例 `10010111,00111000` 留下 3 个，包含真实密钥 `1010000010`；
- 增加不同明文对应的密文可收窄候选，不能保证任何两组都唯一确定密钥；
- 若需严格判断完整行为是否唯一，应比较全部 256 个明文的加密输出。

网页进度条在请求期间显示忙碌动画，接口完成后填满；它不是后端逐个密钥的实时进度。

关于多线程：密钥空间只有 1024、整个穷举约 5 ms，线程调度开销反而占大头，
所以这里多线程**通常不会更快**，它的价值在于演示并行化思路与结果一致性
（`tests/test_all.py` 会断言 workers=1/2/4/16 的结果完全一致）。详见性能基准一节。

#### 想让破解"看得见"？用扩展密钥空间（第 4 关进阶）

> 10 bit 样例穷举为毫秒级，不易从视频中看清搜索过程。附加的级联实验扩大搜索空间，便于展示时间戳与进度；其耗时与结果应与基础 10 bit 实验分开报告。

`sdes/longkey.py` 把 S-DES **级联**成乘积密码，把密钥空间扩到 **10~40 bit**
（每层使用本仓库 `core.py` 的作业版 S-DES，SBox2 仍取作业规定的表）：

```powershell
python -m sdes.longkey --table                  # 先看各长度要跑多久
python -m sdes.longkey --for-seconds 120        # 让它推荐一个跑 ~2 分钟的 --bits
python -m sdes.longkey --bits 22 --interval 5   # ★ 约 1 分 06 秒, 可完整录制
```

| 密钥长度 | 密钥空间 | 预计耗时 |
| --- | --- | --- |
| 10 bit（作业版单层） | 1,024 | 毫秒级，具体耗时取决于运行环境 |
| 20 bit | 1,048,576 | 约 11 秒 |
| **22 bit（默认）** | **4,194,304** | **约 1 分 06 秒** |
| 23 bit | 8,388,608 | 约 2 分 12 秒 |

> 耗时为现场测速后的推算值，会随机器负载浮动（不同 Python 版本速度也不同）。
> 想精确对准某个时长，用 `--for-seconds` 让它推荐，不要死记表里的数字。

输出带**开始/结束时间戳**和**实时进度 + 剩余时间估算**，正是作业要求的「时间戳」证据。
录制与截图步骤见 [`截图说明.md`](截图说明.md) 的图 9 / 图 10。
已提交的演示视频见 [`第4关_破解演示.mp4`](../截图与视频/第4关_破解演示.mp4)。

### 2.7 第 5 关 · 封闭测试

1. 填「样例明文」（0~255，默认 0），点 **运行全空间分析 (1024×256)**。
   程序会真正枚举全部 262144 个 (密钥, 明文) 组合，约需 1~2 秒，期间按钮为忙碌状态。
2. 结果包括：**最大碰撞桶**（多少个密钥能解出同一密文）、**平均候选密钥**
   以及按桶大小统计的分布表。
3. 下面是样例明文的碰撞明细：每个密文对应哪几个密钥。
4. 点 **理论结论（文字报告）** 展开完整分析文本，可直接粘进实验报告。

对作业提出的问题「对任意给定的明文分组 P，是否会出现选择不同的密钥 K_i ≠ K_j
加密得到相同密文 C 的情况？」，答案是 **会**，理由：

- 密钥空间 1024 > 密文空间 256，由**鸽巢原理**，对任一明文必然存在多个密钥映射到同一密文；
- 实测最大桶为 **12 个密钥**，即存在 12 个不同密钥把同一个明文加密成同一个密文；
- 因此固定明文时一定存在密钥碰撞，但不代表每一个可达密文都对应多个密钥；截图的桶大小分布中也有大小为 1 的桶。

需要区分两个概念（页面与文档中都会明确说明）：

| 概念 | 结论 |
|---|---|
| **相同子密钥对** | 当前 `equivalent_key_classes()` 按 `(K1,K2)` 分组；空结果表示未发现相同的子密钥对 |
| **全局等价密钥**（对所有 256 个明文行为完全相同） | 需比较完整加密输出；不同 `(K1,K2)` 本身不足以证明不存在全局等价密钥 |
| **特定明文的碰撞**（只要求对某一个明文加密结果相同） | **大量存在**，正是上面统计的碰撞桶 |

### 3.1 第1关 基本测试 —— 单分组加解密

窗口内容：明文输入框、密钥输入框、结果区、过程明细区。

可用的按钮：

| 按钮 | 作用 |
|---|---|
| 加密 → | 用密钥加密 8-bit 明文，输出二进制与十六进制密文 |
| ← 解密 | 用密钥解密 8-bit 密文，还原明文 |
| 逐步跟踪（供手算比对） | 打印密钥扩展与轮函数的每一个中间量，用于和纸上手算对照 |
| 随机明文/密钥 | 自动生成一组随机输入 |
| 清空 | 清空所有输入输出 |

输入规则：

- 明文必须是 **8 位**由 `0`/`1` 组成的字符串，密钥必须是 **10 位**。
- 输入中的空格与下划线会被自动忽略，所以 `1001 0111` 与 `10010111` 等价。
- 位数不对时不会崩溃，只会弹出提示。

「逐步跟踪」输出的中间量依次为：

```
P10(K)                 密钥经过 P10 置换
L1|R1 (P10 左5|右5)    分为左右两半
K1 / K2                两个子密钥
IP(P)                  明文经过初始置换
L0 / R0                IP 输出的左右两半
F(R0,K1)               轮函数输出
f_K1(IP(P))            第一轮结束
SW(...)                左右 4-bit 交换
F(L1',K2)              第二轮轮函数输出
f_K2(SW(...))          第二轮结束
IP^-1(...) = C         最终密文
```

这份明细正好对应作业给出的加密公式 `C = IP⁻¹( f_K2( SW( f_K1( IP(P) ) ) ) )`，写实验报告时可以直接抄进正文。

### 3.3 第3关 扩展功能 —— 字符串加密与 TCP 通信

**（a）本地字符串加解密**

**（b）TCP Socket 加密通信**


### 3.4 第4关 暴力破解 —— 穷举 10-bit 密钥

界面可调参数：

| 控件 | 含义 | 默认 |
|---|---|---|
| 明文-密文对 | 形如 `10010111,00111000`，多对用 `;` 分隔 | — |
| 线程数 | 多线程模式下的工作线程数 | 8 |
| 每块大小 | 每个线程一次领取的密钥数量 | 64 |
| 多线程 | 勾选则使用线程池，取消则单线程 | 勾选 |
| 随机生成一对（已知真钥匙） | 随机造一个已知密钥的样本，便于验证 | — |

点「开始破解」后，进度条按 `已尝试 / 1024` 推进，结束后列出所有候选密钥、耗时与速率。

预期现象：

- 正确生成的明密文对，其真实密钥一定在候选中；单组可能对应 1 个或多个候选。
- 增加不同明文的密文对通常能收窄候选，具体数量以程序输出为准。

关于多线程：S-DES 的密钥空间只有 1024，单次穷举约 5 ms，线程创建和调度还会增加开销。提交截图显示线程版本更慢；常规启用 GIL 的 CPython 中，纯 Python 计算也不能靠增大线程数获得真正并行。进程实现可参考附加的 `sdes.longkey`，具体收益应由测量判断。

### 3.5 第5关 封闭测试 —— 是否多个密钥得到相同密文？

界面上有两个按钮：

| 按钮 | 作用 |
|---|---|
| 运行全空间分析 (1024×256) | 真实枚举全部 262144 个 (密钥, 明文) 组合并统计 |
| 理论结论 (文字报告) | 直接打印文字版分析报告（秒出） |

全空间分析约需 1~2 秒，统计结果包含：

- 每个明文对应的**不同密文个数**（平均约 239，上限 256）；
- **多密钥 → 同一密文**的桶大小分布与最大桶；
- 结论：固定明文后，密钥空间 1024 > 密文空间 256，由鸽巢原理必然存在 K_i ≠ K_j 使 E(K_i, P) = E(K_j, P)。

因此答案是「**会**」：对任意固定明文，都至少存在一组多密钥同密文的碰撞。它说明单组明密文对可能不能唯一确定密钥，并不保证每个密文桶都有多个密钥。

> 顺带区分两个概念：
> - 当前源码用 `(K1,K2)` 分组统计相同子密钥对；其空结果不能单独证明不存在对所有明文行为相同的全局等价密钥；
> - **针对特定明文的碰撞**则大量存在（最大桶 12 个密钥）。作业第5关问的是后者。

## 5. 常见问题

**Q1：运行命令提示 `ModuleNotFoundError: No module named 'sdes'`。**
当前目录不对。必须先 `cd` 到项目根目录（含 `sdes/`、`tests/` 的那一层）再执行；项目使用 `python -m 包名.模块名` 的方式运行。

**Q2：控制台中文显示为乱码。**
PowerShell 中执行 `$env:PYTHONIOENCODING="utf-8"`；或 `chcp 65001` 把代码页切到 UTF-8。

**Q3：GUI 无法启动，报 `No module named 'tkinter'`。**
Linux 下需单独安装（Debian/Ubuntu：`sudo apt install python3-tk`）；Windows 官方安装包默认自带，若缺失请重新运行安装程序并勾选 tcl/tk 组件。

**Q4：第 3 关发送失败，提示「通信失败」。**
多数情况下是服务端没启动。先在另一个终端运行 `python -m sdes.server`，确认打印出监听信息后再点发送。若改过端口，请确认 GUI 中的端口与服务端一致。

**Q5：我的结果和公开资料上的标准 S-DES 测试向量对不上。**
本作业的 SBox2 被改写（作业原文：「此处的 S-box2 与 PPT 上面的相比略有改动，以此处为准」），公开标准向量不能直接当作本作业的期望输出；具体输入的结果可能相同，也可能不同。正确性应结合规格表核对、手算、独立实现比较和加解密回环。

**Q6：多线程破解为什么没有变快？**
密钥空间只有 1024，整个穷举约 5 ms，线程创建与调度开销占了大头。这是**算法规模决定的，不是程序缺陷**；多线程的价值在于演示并行化思路（详见第 4 关说明）。

**Q7：明文里带换行，会不会把协议搞坏？**
CLI 的 send_message 发出十六进制密文，明文换行不会拆分请求；服务端把解密结果中的反斜杠、回车、换行转义为单行，CLI 与网页版用 _unescape 还原。桌面版目前展示的是原始转义回包；命令行交互输入也会去除首尾空白，因此保留特殊字符时应区分入口。

**Q8：输入密钥或明文时打错了位数怎么办？**
程序会校验长度并给出明确提示，不会静默产生错误结果。GUI 中弹出提示框，命令行中抛出带说明的 `ValueError`。

**Q9：网页版打不开 / 提示无法访问此网站。**
先确认 `python -m sdes.webapp` 的终端还在运行且没有报错；再核对浏览器地址里的端口与终端打印的一致（默认 `8000`）。若终端提示端口被占用，换一个端口重启，例如 `python -m sdes.webapp --port 8080`。

**Q10：网页版要不要联网？会不会把我的数据发出去？**
默认 HTTP 与 TCP 主机均为 `127.0.0.1`，本机演示无需联网。网页后端支持 `--host`，第 3 关也允许填写其他 TCP 主机；使用这些选项时连接对象不再限于本机。DEC 回包是明文，KEY 会返回演示密钥，协议未提供认证或 TLS，仅用于课程演示。

**Q11：网页版和桌面版的结果会不一样吗？**
相同输入经同一内核应得到相同加密结果；两套界面的随机 CSV 取样次序、文本清洗和 TCP 回包处理存在差异。配套测试报告记载的网页版接口自测比对 HTTP 输出与直接调用内核的输出，它验证的是接口一致性，不是独立实现之间的交叉验证。

**Q12：不想装 `tkinter`，还能用吗？**
可以。网页版完全不依赖 `tkinter`，只用到 `http.server` 与 `json`，可以在精简版 Python 环境里正常使用。

**Q13：10 bit 破解为毫秒级，如何在视频里清楚展示过程？**
基础实验仍应记录其自身的样例与耗时；另可运行 `python -m sdes.longkey --bits 22 --interval 5`，以多层作业版 S-DES 展示更大的搜索空间和时间戳。`--bits 10` 退化为本仓库的单层实现，但扩展实验的挑战数据是另行生成的，不等同于 `sdes.crack` 的固定样例。预计时长随机器而变，可用 `--table` 或 `--for-seconds 300` 估算。视频见 [第4关_破解演示.mp4](../截图与视频/第4关_破解演示.mp4)。

**Q14：`--workers` 开了并行，但提示「多进程不可用，已回退单线程」？**
`sdes.longkey --workers` 采用进程；第 4 关网页与桌面界面的线程数则采用线程池。扩展实验默认使用 `crack_subprocess`，以文件交换进度和结果，避免对结果管道的依赖。受限运行环境仍可能禁止启动子进程或写临时文件；具体性能以当次测量为准。
回退时会显示原因，应按当次错误检查权限和运行环境；若还设置了 --max-seconds，回退后的遍历范围与已找到的候选也可能不同，应核对遍历条数和是否提前中止。
当前实现未统一校验子进程非零退出码，结果文件无法读取时会跳过该份额；临时目录创建失败也可能直接报错而不回退。进程结束不等于完整扫描，应核对遍历条数是否等于总空间。

**Q15：扩展密钥空间下，候选密钥跑出来是 2 个而不是 1 个，是 bug 吗？**
多个候选表示当前已知明密文对不能区分它们。配套材料还记载了 L=12 级联构造中不同主密钥对全部 256 个明文给出相同结果的情况；这类全局等价行为无法通过增加同一算法的明密文对区分。只有局部碰撞才可能通过增加不同明文的样例收窄。

**Q16：破解时进度百分比超过 100%（比如 250.0%）？**
那是早期版本的 bug，已修。原因是多个 worker 各自写自己的绝对下标，父进程求和后重复计数。现在 worker 写的是**段内已完成的条数**，父进程求和即为总数。
