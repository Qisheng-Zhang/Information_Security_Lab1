## 1. 基本测试：图 1—3

**要求：** GUI 接收 8-bit 数据、10-bit 密钥，提供加密和解密。

### 图 1：加密与逐步跟踪

在网页第 1 关输入明文 `10010111`、密钥 `1010000010`，点击“加密”和“逐步跟踪”。[原图](../截图与视频/第1关_加密.png) 展示密文 `00111000`／`38`，子密钥 `K1=10100100`、`K2=01000011`。

| 中间状态 | 位串 |
| --- | --- |
| P10(K) | `1000001100` |
| P10 后左右半块 | `10000` / `01100` |
| IP(P) | `01011101` |
| L0、R0 | `0101` / `1101` |
| F(R0,K1) | `1111` |
| 第一轮结果 | `10101101` |
| SW 后 | `11011010` |
| 第二轮 F 输出 | `1111` |
| 第二轮结果 | `00101010` |
| IP⁻¹ 后密文 | `00111000` |

### 图 2：另一组输入的解密

把 `10010111` **作为密文**输入，使用密钥 `1010000010`，点击“解密”。[当前原图](../截图与视频/第1关_解密.png) 输出标题为“明文”，hex `8C` 与二进制 `10001100` 相符。

图 2 展示独立的一次解密操作。复现图 1 的加密—解密回环时，应该输入图 1 的密文 `00111000`，同密钥解密得到 `10010111`；不能把图 2 当作这一回环的截图。

### 图 3：另一组明文与密钥

[原图](../截图与视频/第1关_随机.png) 记录明文 `00111111`、密钥 `0101001001`，密文为 `10101011`／`AB`，子密钥为 `01010010`、`00001100`。可手动输入该组数据重现；“随机明文／密钥”按钮会产生新的输入。

## 2. 交叉测试：图 4 与 CSV

**要求：** 独立程序采用相同流程与转换单元，同一明文和密钥得到相同密文，或者正确解密对方密文。

网页第 2 关生成 200 条测试向量，固定种子为 `20261008`，导入 CSV 后点击“比对”。[原图](../截图与视频/第2关_交叉测试.png) 显示 200/200 行一致；保存的数据为 [对方.csv](../对方.csv)，列名为 `pt,key,ct`。

这一截图记录的是导入数据的一致性。项目内独立生成算法在 [gen_vectors.py](../tests/gen_vectors.py)。外部互验工具在 [cross_test.py](../tests/cross_test.py)，需要另行准备对方源码并指定路径：

```powershell
python -m tests.cross_test --other ..\队友\SDES\sdes --full
```

路径只是示例，需替换为实际目录。外部源码未附在仓库中，历史全空间互验记录及接口条件见 [测试报告](测试报告.md)。两套界面共用内核的一致性与独立实现互验应分别理解。

## 3. 字符串与 TCP：图 5—6

**要求：** ASCII 字符串按 1 Byte 分组加解密，并设计 UI 或扩展应用。

终端 A 执行 `python -m sdes.server`，保持运行；终端 B 执行 `python -m sdes.client`。[图 5](../截图与视频/第3关_服务端与客户端.png) 展示四条消息成功还原，包含英文、中文、单字符和混合符号。中文使用 UTF-8，是项目附加功能。

| 明文 | 截图中的密文（hex） |
| --- | --- |
| `This is a test` | `2268C72762C72762BD624EF8274E` |
| `信息安全导论` | `111E8F92E71DFEE89DFE66DAFE1DE52EE803` |
| `A` | `15` |
| `Hello, S-DES! 1234567890` | `C4F80D0D2F99624F365F504F2962B8CE73BAFD4BD602801F` |

保持服务端运行，另执行 `python -m sdes.webapp --open`，在网页第 3 关输入 `This is a test` 并发送至 TCP 服务端，即可重现 [图 6](../截图与视频/第3关_网页版.png) 的操作。14 字节对应 14 个分组，无需补位。

当前协议的 `DEC` 请求携带十六进制密文，服务端返回解出的明文供校验；`KEY` 返回演示密钥。因此不能把这段演示描述为双向都不传明文的加密通道。完整协议见 [开发手册](开发手册.md)。

## 4. 暴力破解：图 7—10 与视频

**要求：** 已知一个或多个明文—密文对，穷举密钥，记录时间戳并用视频／动图展示耗时；多线程属于可考虑的方案。

### 图 7：课程规定的 10-bit 密钥空间

执行 `python -m sdes.crack`。[原图](../截图与视频/第4关_穷举.png) 记录 `P=10010111`、`C=00111000`，完整遍历 1024 个密钥后留下 `0111001010`、`1010000010`、`1011001010`；真实密钥包含其中，该次耗时 6.00 ms。单个已知对可能保留多个候选。

### 图 8：线程基准

执行 `python -m tests.bench_crack`。[原图](../截图与视频/第4关_性能基准.png) 记录 15 次重复的中位数：单线程 4.885 ms；线程池 workers=1/2/4/8/16 分别为 5.395、5.663、6.228、5.990、6.236 ms。所有候选集合相同，这次测量未观察到提速。

### 图 9：22-bit 完整搜索，附加实验

运行方式：`python -m sdes.longkey --bits 22 --interval 5`。[原图](../截图与视频/第4关_扩展密钥空间22bit.png) 记录三层级联、4 组已知对、单线程，17:37:35 开始，17:38:43 结束，约 68 秒扫描完整的 4,194,304 个候选。唯一候选为 22 位 `1111101010001111111100`。

默认数据随机生成，重新运行同样命令可能产生不同密钥、已知对和候选数。CLI 的参数说明见 [用户指南](用户指南.md)。

### 图 10：24-bit 八进程限时搜索，附加实验

运行方式：`python -m sdes.longkey --bits 24 --workers 8 --max-seconds 10`。[原图](../截图与视频/第4关_并行8进程.png) 记录约 10.1 秒、3,538,944 / 16,777,216 个候选（约 21.1%）。实测速率 352,034 候选/秒与启动前单线程估测速率 76,660 相比约 4.59 倍。

截图底部截断，且搜索范围未完成。这张图可以展示限时搜索和并行速率，不能证明完整空间已经穷举，也不能据此宣布唯一恢复密钥。

### 视频：22-bit 搜索的另一轮完整结果

**[打开／下载第4关_破解演示.mp4](../截图与视频/第4关_破解演示.mp4)**

视频约 65 秒。开头录屏菜单遮挡了部分终端，搜索已在进行；中段显示参数与进度，末段显示完整结束结果：

| 项目 | 视频中的记录 |
| --- | --- |
| 任务 | 22-bit、三层级联、4 组已知对、单线程 |
| 开始／结束时间戳 | `17:21:47` / `17:22:46` |
| 实际搜索耗时 | **59.0 秒** |
| 遍历范围 | **4,194,304 / 4,194,304** |
| 实测速率 | **71,143 候选密钥/秒** |
| 结果 | 命中真实密钥 `True`，留下 **6 个候选** |

视频与图 9 是不同轮次。视频记录完整扫描后仍有多个候选，图 9 记录唯一候选；这两种结果取决于已知对和密钥，分别按画面报告。录像总时长与算法扫描耗时也应分别列出。

## 5. 封闭测试：图 11

**要求：** 分析固定明文时是否存在不同密钥产生相同密文。

在网页第 5 关点击“运行全空间分析”，或执行 `python -m sdes.crack report`。[原图](../截图与视频/第5关_封闭测试.png) 记录完整的 1024 × 256 = 262,144 个组合，平均每个明文有 239 种不同密文，最大碰撞桶包含 12 个密钥。

样例明文 `00000000` 有 224 种密文对应多个密钥。截图中的 4.285 是非空桶平均候选数；含全部密文值（含空桶）的平均为 4。碰撞分布和理论解释见 [测试报告](测试报告.md)。
